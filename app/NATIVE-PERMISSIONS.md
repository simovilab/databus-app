# Native permissions — apply after `npx cap add android` / `npx cap add ios`

The `android/` and `ios/` native projects do not exist in this repo yet
(they're generated by Capacitor, not hand-written). Agent A5 generates them
via `npx cap add android` / `npx cap add ios` and must apply the entries
below to the generated manifests before building. This is a **standalone
Capacitor app** — permissions live directly in the native manifest/plist,
**not** in OutSystems ODC build actions.

These permissions exist to support background GPS telemetry publishing
(master-plan §8 R6, R7) — the driver may lock/pocket the phone mid-run and
the app must keep publishing position over MQTT.

## Android — `android/app/src/main/AndroidManifest.xml`

Add inside `<manifest>`, before/alongside the existing `<application>` tag:

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_BACKGROUND_LOCATION" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_LOCATION" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
```

Notes:
- `ACCESS_BACKGROUND_LOCATION` requires `ACCESS_FINE_LOCATION` to already be
  requested at runtime, and on Android 10+ needs a **separate** runtime
  permission prompt (cannot be requested in the same dialog).
- `FOREGROUND_SERVICE_LOCATION` is required on Android 14+ for a foreground
  service whose type is `location` (Android 14 enforces typed foreground
  services — A5's service must declare `android:foregroundServiceType="location"`
  on the `<service>` element it adds for the telemetry runtime).
- `POST_NOTIFICATIONS` (Android 13+) is required because a foreground
  service must show a persistent notification.
- A5's own `<service>` declaration (with `foregroundServiceType="location"`)
  goes in the plugin's own Android module, not here — this file only covers
  the manifest permissions A1 is responsible for flagging.

## iOS — `ios/App/App/Info.plist`

Add these keys:

```xml
<key>NSLocationWhenInUseUsageDescription</key>
<string>Databús necesita tu ubicación para transmitir tu posición mientras conduces una ruta activa.</string>

<key>NSLocationAlwaysAndWhenInUseUsageDescription</key>
<string>Databús necesita tu ubicación en segundo plano para seguir transmitiendo tu posición cuando el teléfono está bloqueado durante una ruta activa.</string>

<key>UIBackgroundModes</key>
<array>
  <string>location</string>
</array>
```

Notes:
- Coordinate with A5 on whether `processing` and/or `fetch` also need to be
  added to `UIBackgroundModes` — that depends on how the native plugin
  implements store-and-forward flushing (master-plan §8 R7). If A5's
  background flush relies on BGTaskScheduler / background fetch, add the
  corresponding mode and register the matching `BGTaskSchedulerPermittedIdentifiers`
  entry.
- iOS also requires enabling the **Background Modes → Location updates**
  capability in Xcode (this writes the same `UIBackgroundModes` key but is
  usually toggled via the Signing & Capabilities tab after `cap open ios`).

## Where this fits the build

```
npm install ./plugins/capacitor-databus-telemetry   # A5's native plugin package
npx cap add android && npx cap add ios              # generates android/ ios/
# apply the entries above to the generated manifest/plist
npx cap sync
npx cap run android   # or: npx cap run ios
```
